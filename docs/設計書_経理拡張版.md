### 4.3 入金管理・入金消込

| # | 機能 | 優先度 | 説明 |
|---|------|--------|------|
| C1 | 入金登録 | 高 | 請求に対する入金を記録 |
| C2 | 入金消込処理 | 高 | 入金と請求書の突合・消込。請求残高（＝請求額−入金額）を自動算出 |
| C3 | 一部入金対応 | 高 | 請求額＞入金額の場合、未収残高を管理。複数回入金に対応 |
| C4 | 過入金対応 | 中 | 請求額＜入金額の場合（balance < 0）、過入金分を①次回請求のcarried_over_amountに充当（マイナス値で設定）、または②返金記録を作成。処理選択は経理担当者がUI上で判断 |
| C5 | 未収管理 | 高 | 未入金の請求一覧、経過日数表示、請求残高表示 |
| C6 | 繰越管理 | 中 | 未収分の翌月繰越 |

**入金消込の計算ロジック:**
```
請求残高 = 請求額(total_amount) + 繰越額(carried_over_amount) − 入金済額(paid_amount)

・請求残高 > 0 → 未収（partial or overdue）
・請求残高 = 0 → 入金済（paid）
・請求残高 < 0 → 過入金（overpaid）→ 次回充当 or 返金
```

### 4.3.1 請求生成アルゴリズム

```
【請求生成条件】
  対象: type = 'cash_advance'  -- ※ transactions.type カラム
        AND billing_status = 'unbilled'
        AND billing_year = 対象年
        AND billing_month = 対象月
        AND approval_status = 'approved'

【処理フロー】
  1. 未請求の立替取引を上記条件で抽出
  2. resident_id ごとにグループ化し金額を集計
  3. resident ごとに billings レコードを作成
     - billing_number: INV-YYYYMM-XXXX（月内連番）
     - total_amount: 対象取引の合計額
     - carried_over_amount: 前月の未収残高があれば加算
     - status: 'draft'
  4. 各取引に対して billing_items レコードを作成
     - amount: transaction.amount（※将来の分割・部分・調整請求に備え独立カラムとして保持）
  5. 対象 transactions の billing_status を 'billed' に更新
     billing_id に作成した billings.id を設定

【重複防止】
  billing_items に UNIQUE(transaction_id) 制約を設定
  → 同一取引が複数請求に含まれることを防止
```

### 4.3.2 入金消込フロー

```
【入金登録時の処理】
  1. payments レコードを作成（amount は常に正数）
  2. 対象 billings の paid_amount を更新
     payment_kind = 'receipt' の場合: paid_amount += payment.amount
     payment_kind = 'refund'  の場合: paid_amount -= payment.amount
  3. balance（生成列）が自動再計算
     balance = total_amount + carried_over_amount - paid_amount
  4. balance に基づき billings.status を更新:
     balance = 0  → 'paid'
     balance > 0  → 'partial'
     balance < 0  → 'overpaid'
  5. 紐付く transactions の billing_status を更新:
     全額入金済 → 'paid'
     一部入金  → 'partial'
```

### 4.3.3 過入金処理フロー

```
【過入金発生時】(balance < 0)
  billings.status → 'overpaid'

  ┌─────────────────┐
  │ 過入金を検知     │
  │ (balance < 0)   │
  └────────┬────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
  ┌──────┐  ┌──────┐
  │ 充当  │  │ 返金  │
  └──┬───┘  └──┬───┘
     │          │
     ▼          ▼
  次回請求の    返金記録を作成
  carried_over  (payments に
  にマイナス    payment_kind='refund'
  値で設定      amount=正数 で記録)

【充当の場合】
  1. 経理担当者がUI上で「次回充当」を選択
  2. 翌月の billings 作成時に carried_over_amount に過入金分を
     マイナス値として設定（実質的に請求額が減額される）

【返金の場合】
  1. 経理担当者がUI上で「返金」を選択
  2. payments テーブルに返金レコードを作成（payment_kind='refund', amount=返金額（正数））
  3. billings の paid_amount から返金額を減算 → balance = 0 に調整
```

### 4.3.4 利用者残高ロジック

```
【利用者残高の定義】
  resident_balance =
    sum(未請求立替額: transactions WHERE billing_status = 'unbilled'
                      AND type = 'cash_advance'  -- ※ transactions.type
                      AND resident_id = ?)
    +
    sum(未入金請求残高: billings.balance WHERE resident_id = ?
                        AND status NOT IN ('paid', 'cancelled'))

【表示画面】 /advance-payments
  ┌──────────┬──────────┬──────────┬──────────┐
  │ 利用者名  │ 未請求額  │ 未入金額  │ 総残高    │
  ├──────────┼──────────┼──────────┼──────────┤
  │ 田中太郎  │  12,500  │   8,000  │  20,500  │
  │ 鈴木花子  │   5,000  │       0  │   5,000  │
  │ ...      │    ...   │    ...   │    ...   │
  └──────────┴──────────┴──────────┴──────────┘

【集計API（Supabase RPC）】
  関数名: get_resident_balance(p_resident_id UUID)
  戻り値: { unbilled_amount, unpaid_amount, total_balance }

  SQL:
    SELECT
      COALESCE(SUM(t.amount) FILTER (
        WHERE t.billing_status = 'unbilled'
        AND t.type = 'cash_advance'  -- ※ transactions.type
      ), 0) AS unbilled_amount,
      COALESCE(SUM(b.balance) FILTER (
        WHERE b.status NOT IN ('paid', 'cancelled')
      ), 0) AS unpaid_amount,
      (unbilled_amount + unpaid_amount) AS total_balance
    FROM ...
```

## 7. DB変更案

### 7.1 既存テーブル拡張

#### transactions テーブルへのカラム追加

```sql
ALTER TABLE transactions ADD COLUMN
  billing_status TEXT DEFAULT 'unbilled'
    CHECK (billing_status IN ('unbilled', 'billed', 'paid', 'partial', 'carried_over')),
  billing_id UUID REFERENCES billings(id),
  billing_year INTEGER,   -- 請求対象年（例: 2026）
  billing_month INTEGER,  -- 請求対象月（例: 3）
  is_over_limit BOOLEAN NOT NULL DEFAULT FALSE,            -- 立替上限超過フラグ
  over_limit_approved_by UUID REFERENCES employees(id),    -- 上限超過承認者
  over_limit_approved_at TIMESTAMPTZ;                      -- 上限超過承認日時
```

| カラム | 型 | 説明 |
|--------|-----|------|
| location_id | UUID NOT NULL | 取引の所属拠点 `REFERENCES locations(id)`。**既存カラム**（拠点精算・月次集計・インデックスで使用） |
| billing_status | TEXT | 未請求/請求済/入金済/一部入金/繰越 **※キャッシュカラム**（billing_items/billings/paymentsから算出可能だが高速参照のため保持。更新タイミング: ①請求作成時→billed ②入金時→partial/paid ③繰越時→carried_over） |
| billing_id | UUID | 紐付き請求書（NULLable） |
| billing_year | INTEGER | 請求対象年（NULLable。立替金以外の取引はNULL） |
| billing_month | INTEGER | 請求対象月（NULLable。立替金以外の取引はNULL） |
| is_over_limit | BOOLEAN | 立替上限超過フラグ（DEFAULT FALSE）。上限超過時にtrueを設定 |
| over_limit_approved_by | UUID | 上限超過を承認したSV/管理者のID `REFERENCES employees(id)` |
| over_limit_approved_at | TIMESTAMPTZ | 上限超過承認日時 |

> **transactions.location_id について:** このカラムは既存テーブルに存在するカラムであり、拠点精算（settlementsの集計元）、月次集計、SV締め判定、およびインデックス `idx_transactions_location_period` の基盤となる。新規追加ではなく既存カラムの設計上の明示。

> **変更理由:** TEXT型('YYYY-MM')はフォーマット揺れ（'2026-3' vs '2026-03'等）のリスクがあるため、INT×2に変更。全テーブルで統一。

※ resident_id は既存のままNULL可を維持。cash_advance時はUIバリデーションで入力必須とするが、共通費・ホーム備品・共通生活費等はresident_id=NULLで登録可能。

#### residents テーブルへのカラム追加

```sql
ALTER TABLE residents ADD COLUMN
  advance_limit INTEGER,       -- 立替上限額（NULL=上限なし）
  billing_name TEXT,           -- 請求先名（利用者と異なる場合）
  billing_address TEXT,        -- 請求先住所
  billing_postal_code TEXT,    -- 請求先郵便番号
  billing_contact TEXT,        -- 請求先連絡先
  billing_notes TEXT;          -- 請求備考
```

**立替上限チェックロジック:**
```
立替登録時:
  1. 対象利用者の advance_limit を取得
  2. advance_limit が NULL → チェックなし（上限なし）
  3. advance_limit が設定済み:
     現在残高 = get_resident_balance(resident_id).total_balance
     if (現在残高 + 登録額) > advance_limit:
       → 警告ダイアログを表示
       → SV以上の承認が必要（home_managerは登録不可）
       → 承認後は登録可能（上限を超えた状態で記録）

  【DB記録（上限超過時）】
  4. 上限超過の場合、transactions に以下を設定:
     is_over_limit = TRUE
  5. SV承認時に以下を設定:
     over_limit_approved_by = 承認者のemployee_id
     over_limit_approved_at = 承認日時
  6. audit_logs にも上限超過承認の記録を残す:
     action = 'over_limit_approved'
     table_name = 'transactions'
     new_data に承認者・承認日時・超過額を記録
```

#### billings（請求書）

```sql
CREATE TABLE billings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  billing_number TEXT NOT NULL UNIQUE,     -- 請求書番号（自動採番）
  location_id UUID NOT NULL REFERENCES locations(id),
  resident_id UUID REFERENCES residents(id), -- NULL可（共通費の請求に対応）
  billing_year INTEGER NOT NULL,           -- 請求対象年（例: 2026）
  billing_month INTEGER NOT NULL,          -- 請求対象月（例: 3）
  billing_date DATE NOT NULL,             -- 請求日
  due_date DATE,                          -- 支払期限
  total_amount INTEGER NOT NULL,          -- 請求合計額（当月立替分）
  carried_over_amount INTEGER NOT NULL DEFAULT 0, -- 前月繰越額
  paid_amount INTEGER NOT NULL DEFAULT 0, -- 入金済み額
  balance INTEGER NOT NULL GENERATED ALWAYS AS
    (total_amount + carried_over_amount - paid_amount) STORED, -- 請求残高（自動算出）
  status TEXT NOT NULL DEFAULT 'draft'
    CHECK (status IN ('draft', 'issued', 'sent', 'partial', 'paid', 'overpaid', 'overdue', 'cancelled')),
  notes TEXT,
  created_by UUID NOT NULL REFERENCES employees(id),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

> **変更理由:**
> - `resident_id`: NULL可に変更。共通費の請求に対応。
> - `billing_year/billing_month`: TEXT→INT×2に統一。
> - `balance`: 請求残高を生成列として追加。`total_amount + carried_over_amount - paid_amount` で自動算出。
> - `status`: `overpaid`（過入金）を追加。

#### billing_items（請求明細）

```sql
CREATE TABLE billing_items (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  billing_id UUID NOT NULL REFERENCES billings(id) ON DELETE CASCADE,
  transaction_id UUID NOT NULL REFERENCES transactions(id),
  amount INTEGER NOT NULL,
    -- ※ transaction.amount と通常は同額だが、以下の用途で独立カラムとして保持:
    --   ・将来の分割請求（1取引を複数請求に分割）
    --   ・部分請求（取引額の一部のみ請求）
    --   ・金額調整（端数調整・値引き等）
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(transaction_id) -- 重複防止: 同一取引を複数請求に含めない
);
```

#### payments（入金）

```sql
CREATE TABLE payments (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  billing_id UUID NOT NULL REFERENCES billings(id),
  payment_date DATE NOT NULL,
  amount INTEGER NOT NULL CHECK (amount > 0),  -- 常に正数。返金も正数で記録
  payment_kind TEXT NOT NULL DEFAULT 'receipt'
    CHECK (payment_kind IN ('receipt', 'refund')),
    -- receipt: 通常入金（paid_amount に加算）
    -- refund:  返金（paid_amount から減算）
  payment_method TEXT DEFAULT 'transfer'
    CHECK (payment_method IN ('transfer', 'cash', 'other')),
  notes TEXT,
  recorded_by UUID NOT NULL REFERENCES employees(id),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

> **返金の扱い:** `amount` は常に正数。返金は `payment_kind = 'refund'` で区別する（`amount < 0` は使用しない）。集計・残高計算時は `payment_kind` を考慮して加減算する。

#### settlements（拠点精算）※計算結果のキャッシュテーブル（transactions + payments から再計算可能）

```sql
CREATE TABLE settlements (

  replenishment_amount INTEGER NOT NULL,       -- 補充必要額
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'requested', 'transferred', 'confirmed')),
  transfer_date DATE,
  transfer_amount INTEGER,
  transferred_by UUID REFERENCES employees(id),
  confirmed_by UUID REFERENCES employees(id),
  confirmed_at TIMESTAMPTZ,
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(location_id, settlement_year, settlement_month)
);
```

**入金消込ロジック（balanceカラムによる自動判定）:**
```
balance = total_amount + carried_over_amount − paid_amount （DB生成列）

balance > 0  かつ paid_amount = 0         → sent / issued（未入金）
balance > 0  かつ paid_amount > 0         → partial（一部入金）
balance = 0                               → paid（入金済）
balance < 0                               → overpaid（過入金）
balance > 0  かつ due_date < current_date → overdue（期限超過）
```

   - 修正内容は監査ログに自動記録される
   - MonthlyCloseのステータスが自動的に `modified` に変更
   - modification_count がインクリメント
3. SVが再確認後、再度「closed」に戻す（SV再締め）

### 全銀フォーマット仕様（参考）

振込依頼CSVは以下の全銀協規定フォーマットで出力:

```
【ヘッダーレコード】(1レコード)
  区分コード(1) + 種別コード(2) + コード区分(1) + 振込依頼人コード(10)
  + 振込依頼人名(40) + 振込日(4) + 仕向銀行番号(4) + 仕向銀行名(15)
  + 仕向支店番号(3) + 仕向支店名(15) + 預金種目(1) + 口座番号(7)
  + ダミー(17)

【データレコード】(N件 — settlementsの各拠点分)
  区分コード(1) + 銀行番号(4) + 銀行名(15) + 支店番号(3)
  + 支店名(15) + 手形交換所番号(4) + 預金種目(1) + 口座番号(7)
  + 受取人名(30) + 振込金額(10) + 新規コード(1) + 顧客コード1(10)
  + 顧客コード2(10) + 振込区分(1) + ダミー(8)

【トレーラーレコード】(1レコード)
  区分コード(1) + 合計件数(6) + 合計金額(12) + ダミー(101)

【エンドレコード】(1レコード)
  区分コード(1) + ダミー(119)
```
